> **Weeks 15–16** · NeetCode section: **1-D DP** · Target: **11 new problems** (W15: 8, W16: 3) + stretch pool · Java rep: **198** (Week 15)
> Back to [DSA overview](./README.md) · Tracker: [`trackers/dsa-tracker.md`](../trackers/dsa-tracker.md#18--dynamic-programming-1-d) · Python: [`19-python/03-pitfalls-and-complexity.md`](../19-python/03-pitfalls-and-complexity.md) (`functools.cache`, recursion limit) · Java: [quick reference](./java-dsa-toolkit.md)

Dynamic programming = **recursion + memory**. When a recursive solution recomputes the same subproblems, store each answer once (memoisation, top-down) or fill a table in dependency order (tabulation, bottom-up). 1-D DP means the state is a single index (position, amount, length). The skill is not the code — it's **defining the state and the recurrence** in words before typing.

---

## 1. Concepts to learn

| Concept | Explanation |
|---|---|
| Optimal substructure | The answer for a state is built from answers of smaller states |
| Overlapping subproblems | The same state is reached many times → caching pays off (naive Fibonacci: 2ⁿ calls, n distinct states) |
| State | "`dp[i]` = the answer for the prefix ending at i / the first i items / amount i." Write it as one sentence |
| Recurrence (transition) | How `dp[i]` depends on smaller states, e.g. `dp[i] = max(dp[i-1], dp[i-2] + nums[i])` |
| Base cases | The smallest states you can answer directly (`dp[0]`, `dp[1]`, amount 0) |
| Answer location | `dp[n]`, `dp[n-1]`, `max(dp)`, … — say which |
| Top-down (memo) | Recursive function + `@functools.cache`. Easiest to derive from brute force. Python: watch the recursion limit (n up to 10⁴ → raise it or tabulate) |
| Bottom-up (tabulation) | Loop over states in dependency order filling a list. No recursion; usually faster in Python |
| Space optimisation | If `dp[i]` only needs `dp[i-1]`, `dp[i-2]` → two variables, O(1) space |
| Unbounded vs 0/1 choices | Coin Change (reuse coins): loop amounts outer or coins outer — both work for min count. 0/1 knapsack (416): iterate the capacity **downwards** |
| Complexity | #states × work per transition |
| LIS in O(n log n) | Patience sorting: `tails` list + `bisect_left` |

The five-step recipe, every time: **(1)** brute-force recursion → **(2)** identify the changing parameters = state → **(3)** memoise → **(4)** convert to a bottom-up table → **(5)** compress space if possible.

## 3. Python implementation

```python
import sys
from bisect import bisect_left
from functools import cache


# ---------- The five-step recipe on House Robber (LC 198) ----------
def rob_brute(nums: list[int]) -> int:              # (1) brute force: O(2^n)
    def best(i: int) -> int:                        # best loot from houses i..n-1
        if i >= len(nums):
            return 0
        return max(best(i + 1), nums[i] + best(i + 2))
    return best(0)


def rob_memo(nums: list[int]) -> int:               # (2)+(3) state = i, memoised: O(n)
    @cache
    def best(i: int) -> int:
        if i >= len(nums):
            return 0
        return max(best(i + 1), nums[i] + best(i + 2))
    return best(0)


def rob_table(nums: list[int]) -> int:              # (4) bottom-up table: O(n) time, O(n) space
    n = len(nums)
    dp = [0] * (n + 2)                              # dp[i] = best from i..n-1; dp[n] = dp[n+1] = 0
    for i in range(n - 1, -1, -1):
        dp[i] = max(dp[i + 1], nums[i] + dp[i + 2])
    return dp[0]


def rob(nums: list[int]) -> int:                    # (5) two variables: O(1) space
    take_prev, best_prev = 0, 0                     # best up to i-2, best up to i-1
    for x in nums:
        take_prev, best_prev = best_prev, max(best_prev, take_prev + x)
    return best_prev


# ---------- Other 1-D templates ----------
def climb_stairs(n: int) -> int:                    # ways(i) = ways(i-1) + ways(i-2)
    a, b = 1, 1
    for _ in range(n - 1):
        a, b = b, a + b
    return b


def coin_change(coins: list[int], amount: int) -> int:
    INF = amount + 1                                # "impossible" sentinel that can't overflow
    dp = [0] + [INF] * amount                       # dp[a] = min coins for amount a
    for a in range(1, amount + 1):
        for c in coins:
            if c <= a and dp[a - c] + 1 < dp[a]:
                dp[a] = dp[a - c] + 1
    return dp[amount] if dp[amount] != INF else -1


def word_break(s: str, words: list[str]) -> bool:
    word_set, n = set(words), len(s)
    max_len = max(map(len, words), default=0)
    dp = [True] + [False] * n                       # dp[i] = s[:i] can be segmented
    for i in range(1, n + 1):
        for j in range(max(0, i - max_len), i):
            if dp[j] and s[j:i] in word_set:
                dp[i] = True
                break
    return dp[n]


def length_of_lis(nums: list[int]) -> int:
    tails: list[int] = []                           # tails[k] = smallest tail of an increasing subsequence of length k+1
    for x in nums:
        i = bisect_left(tails, x)
        if i == len(tails):
            tails.append(x)
        else:
            tails[i] = x
    return len(tails)


def can_partition(nums: list[int]) -> bool:        # 0/1 knapsack on a 1-D table
    total = sum(nums)
    if total % 2:
        return False
    target = total // 2
    dp = [True] + [False] * target                  # dp[s] = some subset sums to s
    for x in nums:
        for s in range(target, x - 1, -1):          # DOWNWARDS: each number used at most once
            dp[s] = dp[s] or dp[s - x]
    return dp[target]


houses = [2, 7, 9, 3, 1]
assert rob_brute(houses) == rob_memo(houses) == rob_table(houses) == rob(houses) == 12
assert climb_stairs(1) == 1 and climb_stairs(5) == 8
assert coin_change([1, 2, 5], 11) == 3 and coin_change([2], 3) == -1 and coin_change([1], 0) == 0
assert word_break("leetcode", ["leet", "code"]) and not word_break("catsandog", ["cats", "dog", "sand", "and", "cat"])
assert length_of_lis([10, 9, 2, 5, 3, 7, 101, 18]) == 4
assert can_partition([1, 5, 11, 5]) and not can_partition([1, 2, 3, 5])


# ---------- Deep top-down recursion in Python ----------
sys.setrecursionlimit(20_000)                       # memo recursion depth ~ n: raise consciously...
memo: dict[int, int] = {}


def ways_dict(i: int) -> int:                       # hand-written dict memo: plain Python frames
    if i <= 1:
        return 1
    if i not in memo:
        memo[i] = ways_dict(i - 1) + ways_dict(i - 2)
    return memo[i]


@cache
def ways_cached(i: int) -> int:
    return 1 if i <= 1 else ways_cached(i - 1) + ways_cached(i - 2)


assert ways_dict(9000) > 0
try:
    ways_cached(9000)                               # ...but on Python 3.12+ the C-implemented @cache wrapper
except RecursionError:                              # hits a separate C recursion limit (a few thousand frames)
    print("@cache recursion too deep on this Python version — tabulate instead")
print("1-D DP templates ok")
```

## 4. The same in Java (occasional reps)

**This week's Java rep (Week 15): 198 House Robber.**

| Python | Java |
|---|---|
| `@cache` on a nested function | `int[] memo` + `Arrays.fill(memo, -1)` + a private helper |
| `dp = [0] * (n + 1)` | `int[] dp = new int[n + 1];` |
| `float("inf")` / `amount + 1` sentinel | `amount + 1` (never `Integer.MAX_VALUE + 1` → overflow) |
| `a, b = b, a + b` | `int t = a + b; a = b; b = t;` |
| ways "mod 10⁹+7" | `long` + `% MOD` after every addition |

```java
class HouseRobberRep {
    static int rob(int[] nums) {
        int takePrev = 0, bestPrev = 0;          // best up to i-2, best up to i-1
        for (int x : nums) {
            int best = Math.max(bestPrev, takePrev + x);
            takePrev = bestPrev;
            bestPrev = best;
        }
        return bestPrev;
    }

    public static void main(String[] args) {
        System.out.println(rob(new int[]{2, 7, 9, 3, 1}) + " " + rob(new int[]{1, 2, 3, 1}));   // 12 4
    }
}
```

## 5. Common patterns (sub-variants)

| Sub-pattern | State / recurrence | Problems |
|---|---|---|
| Fibonacci-style counting | `dp[i] = dp[i-1] + dp[i-2]` (+ `dp[i-3]`) | 70, 1137 |
| Min cost path on a line | `dp[i] = cost[i] + min(dp[i-1], dp[i-2])` | 746 |
| Take / skip | `dp[i] = max(dp[i-1], dp[i-2] + x)` | 198, 213 (run twice: skip first / skip last) |
| Expand around centre (palindromes) | 2n − 1 centres; O(n²) time, O(1) space | 5, 647 |
| Decoding / counting ways over a string | `dp[i] += dp[i-1]` if one digit valid, `+= dp[i-2]` if two digits valid | 91 |
| Unbounded knapsack (min count) | `dp[a] = min(dp[a - c] + 1)` | 322 |
| Segmentation | `dp[i] = any(dp[j] and s[j:i] in words)` | 139 |
| LIS | O(n²) `dp[i] = 1 + max(dp[j] for j < i if a[j] < a[i])`, or O(n log n) tails + `bisect` | 300 |
| Track max and min (sign flips) | keep `cur_max`, `cur_min` | 152 |
| 0/1 subset sum | boolean table, iterate sum downwards | 416 |

## 6. How to recognise the pattern

- "Number of ways", "minimum/maximum cost/profit", "can you reach/form/partition", "longest … subsequence".
- Choices at each step whose best outcome depends on earlier choices (take/skip, which coin, where to cut).
- A brute-force recursion with **repeated arguments** (draw two levels of the tree — do you see the same call twice?).
- Constraints: n ≤ 10³–10⁴ with O(n²) acceptable, or amount ≤ 10⁴ with O(amount · coins).
- Counter-signals: "return all combinations" → backtracking; a local choice that provably never needs revisiting → greedy ([20](./20-greedy.md)).

## 11. Mistakes beginners commonly make

**Python-specific**
- **Mutable default memo** `def f(i, memo={})` → shared across calls and LeetCode test cases → wrong answers on later tests. Use `@cache` on a nested function (fresh per call) or pass the dict explicitly.
- `@cache` on a function taking a `list` → `TypeError: unhashable`; pass indices or `tuple(...)`.
- Top-down on n = 10⁴ → `RecursionError`. `sys.setrecursionlimit` helps plain functions, but on **Python 3.12+ a `@cache`/`@lru_cache`-decorated function hits a separate C-level limit** after a few thousand nested calls even with a raised limit (see §3). For deep state spaces: tabulate (bottom-up), or use a hand-written dict memo.
- `dp = [[0] * m] * n` (2-D aliasing — also bites here when you store pairs).
- `float("inf")` in integer tables is fine in Python, but returning it (instead of −1) is a bug; `amount + 1` keeps the table integral.
- `s[j:i] in word_set` costs O(i − j) for the slice — fine, but count it in the complexity.
- `/` instead of `//` for the partition target.

**General**
- Coding before writing the state definition in one sentence.
- Wrong base case (`dp[0]` for "amount 0" is 0 coins; for "ways to make 0" it's 1).
- 213: forgetting the n = 1 case.
- 91: treating `"0"` / `"06"` as valid.
- 322: trying greedy (largest coin first).
- 416: iterating the sum upwards → reuses the same number (turns 0/1 into unbounded).

**Java-rep traps (198):** `Integer.MAX_VALUE + 1` sentinels overflow; memo arrays need `Arrays.fill(memo, -1)`.

## Worked example — 322. Coin Change

**Clarify.** `coins` (1 ≤ len ≤ 12, values 1..2³¹−1, distinct), `amount` 0..10⁴. Unlimited coins of each type. Return the **fewest** coins that sum to `amount`, or −1 if impossible. `amount = 0` → 0.

**Brute force.** Try every coin at every step recursively: `f(a) = 1 + min(f(a - c))` → exponential (branching 12, depth up to 10⁴). Greedy "largest coin first" is **wrong**: coins `[1, 3, 4]`, amount 6 → greedy 4+1+1 = 3 coins, optimal 3+3 = 2.

**Optimise.** State: `dp[a]` = fewest coins to make amount `a`. Recurrence: `dp[a] = 1 + min(dp[a - c])` over coins `c ≤ a`. Base: `dp[0] = 0`. Answer: `dp[amount]`, with a sentinel `amount + 1` meaning "impossible" (you can never need more than `amount` coins because the smallest coin is ≥ 1). Top-down with `@cache` works too, but recursion depth can reach 10⁴ in Python — bottom-up avoids that.

**Code (Python).**

```python
from functools import cache


def coin_change(coins: list[int], amount: int) -> int:
    INF = amount + 1
    dp = [0] + [INF] * amount
    for a in range(1, amount + 1):
        for c in coins:
            if c <= a:
                dp[a] = min(dp[a], dp[a - c] + 1)
    return dp[amount] if dp[amount] <= amount else -1


def coin_change_memo(coins: list[int], amount: int) -> int:
    @cache
    def fewest(a: int) -> float:
        if a == 0:
            return 0
        best = float("inf")
        for c in coins:
            if c <= a:
                best = min(best, fewest(a - c) + 1)
        return best

    ans = fewest(amount)
    return -1 if ans == float("inf") else int(ans)


for f in (coin_change, coin_change_memo):
    assert f([1, 2, 5], 11) == 3            # 5 + 5 + 1
    assert f([2], 3) == -1
    assert f([1], 0) == 0
    assert f([1, 3, 4], 6) == 2             # greedy would say 3
    assert f([2147483647], 2) == -1         # huge coin never fits
print("322 worked example passed")
```

**Test cases.** `[1,2,5], 11` → 3 · impossible `[2], 3` → −1 · `amount = 0` → 0 · greedy counterexample `[1,3,4], 6` → 2 · a coin larger than the amount → −1.

**Complexity.** Time O(amount · len(coins)) = 10⁴ · 12 ≈ 1.2·10⁵ steps. Space O(amount). (The memo version has the same complexity but recursion depth up to `amount / min(coin)` — fine here for small tests, risky for amount = 10⁴ with coin 1 unless you raise the recursion limit.)
